# CLAUDE.md - nb-prober

One bash script, `bin/nb-prober`, on top of `curl` and `jq`: it checks the monitors of a registered probe from inside a private network, with its own checker, and reports the outcomes to NASEBANAL Evolution (`nb-assurance-api`). It lives under `apps/` because it follows the Assurance contract (probes: `listProbeMonitors` and `reportProbeResults`, authenticated by the probe's own key). The design and its decisions: `apps/docs/push-monitors-design.md`. MIT (`Copyright (c) 2026 NASEBANAL`). User docs: `README.md`. The workspace rules (git, PRs, commit prefixes) are in `apps/CLAUDE.md`.

## Rules

- **Outgoing requests only, and only to two places**: the Evolution API and the URLs of the probe's own monitors (`http` / `https`, `GET` / `HEAD`). Never run anything received from the network.
- **The judgement is Evolution's checker, not a new one**: `nb-assurance-api` `src/services/checker.ts` (redirects followed, 2xx / 3xx when no status is set, keyword on `GET` in the first 1 MiB, `response_ms` = time to the headers, one immediate retry, the final attempt reported). When that file changes, change `probe_once` and the README table with it; a monitor must mean the same in the cloud and on a probe.
- **Settings live in Evolution only**: every pass re-reads the monitors; nothing about a monitor is configured on the probe (no config file, no per-monitor flags). Do not add one.
- **The key never appears in the arguments of a running process, a log or a test output**: curl gets it on stdin (`-K -`), the service reads it from a root-only file. The one exception is `service install KEY`, a single short-lived command (like `cloudflared service install <token>`; the shell history keeps it either way, so stdin buys only `ps`). It is also accepted on stdin and as `NB_PROBER_KEY`. Tests use a dummy key and assert it is not in `args.log`. The key is `nbp_<probe id>_<secret>` and does ONE thing (list this probe's monitors, report their results): never ask for more, and never accept a personal access token here.
- **An edited monitor is checked at once** (`cycle`: due = its interval has passed OR its `updated_at` differs from the one seen at the last check, kept in `<state>/<probe>/updated/<monitor id>`). The edit time is compared for DIFFERENCE, never with this machine's clock (a clock that disagrees with Evolution's must not make it loop), and a monitor the server gives no `updated_at` for falls back to the interval. This replaces a "check now" button for a Private monitor (Evolution never calls the probe): the result of an edit shows within one pass.
- **Service commands run themselves through sudo** (`svc_elevate`): when not root, `nb-prober service ...` (and `nb prober service ...`) executes `sudo env NB_PROBER_ELEVATED=1 <real script path> <the same arguments>` once, so no `sudo` is typed and `nb` need not be on root's PATH; the key and the address that came from the environment are added as arguments (sudo drops the environment). `NB_PROBER_ELEVATED` stops a loop; `--dry-run` and `--root` never elevate; `-n` is checked before sudo. Help text never tells to type `sudo`. The tests put `test/shim/sudo` first on PATH, which only logs.
- **`service create` never takes over an existing service** (`svc_refuse_if_exists`, checked before the key is sent to Evolution, also for `--dry-run`): the unit / plist is the test, the probe it belongs to is named when root can read it; `--force` replaces it in one step. A silent takeover by a wrongly pasted key would stop a running probe and leave its monitors with "no report".
- **`service create` is the way to run it on a machine** (`install` / `uninstall` of the first release still work as aliases; they read like installing nb-prober itself, hence `create` / `delete`) (Ubuntu: systemd, macOS: launchd; `--os` / `--root` exist for tests). The key arrives as the argument (`service install KEY`), on stdin or as `NB_PROBER_KEY`, is verified against Evolution before anything is written, and the file holding it is made mode 600 BEFORE the key is written. Evolution's probe-key screen shows the same command with the key filled in: keep the two in step.
- **A release is one tag; the install steps live in the README, and Evolution links to them.** `bin/tag.sh set vX.Y.Z --repos nb-prober` (the user's step: it publishes) runs `.github/workflows/release.yml`: the tests pass, the released copy of `bin/nb-prober` has its `VERSION` set from the tag (on `main` it says `dev`, so there is no version-bump PR), and the release carries `nb-prober` and `nb-prober.sha256` (of the stamped copy). The README's `## Install` section (anchor `#-install`) fetches `releases/latest/download`, checks the checksum and installs to `/usr/local/bin`; Evolution's probe-key screen shows only the register command and links to that section, so a release needs no Evolution change. Keep the anchor, or change the link in `nb-evolution` `src/tools/assurance/lib/probes.ts` (`PROBER_INSTALL_URL`) with it.
- **Asking for the monitors is the heartbeat**: Evolution shows the probe online while it hears it (2 minutes), so a pass must stay at most 60 seconds (`NB_PROBER_TICK` is refused above it). Every request carries `X-Prober-Version`.
- **Silence is a failure**: a probe that stops reporting is shown by Evolution as `no_report`. Do not paper over it (no fake results while Evolution is unreachable: buffer the real ones).
- **Never lose data silently, never loop for ever**: a report that can never be accepted (400 / 404 / 409) is dropped with a warning; one that may be accepted later (no answer, 5xx, 401 / 403) stays in the buffer.
- **The script's help is the comment block after the shebang** (the same layout as `nb`, `nb-secrets` and `nb-quickstarts`: Usage, one description line, Commands, Options). `nb -h` reads its first line (`# nb-prober - ...`), so keep that line one sentence under 100 characters. Every command answers `-h`; run `bin/nb-prober -h` after changing the header.
- Keep it dependency-light: bash 3.2-safe, `curl`, `jq`, ordinary POSIX tools. No new runtime dependency without a reason that outweighs "the whole script can be read in one sitting".
- Error values and field names come from the contract (`nb-api-specs` `packages/assurance`): `timeout`, `connection_failed`, `unexpected_status`, `keyword_not_found` (never `no_report`, which only the server writes). Change them together with the spec.
- Run `bin/nb-prober -h`, `test/run.sh` and `shellcheck bin/nb-prober test/run.sh test/shim/curl` before proposing a change. The test double cannot catch a wrong `curl` flag: after changing how `curl` is called, also run `nb-prober check` against a real local server (timeout, redirect, keyword, refused port, a body over 1 MiB).
- Docs are English. Plain ASCII numbering (no circled digits).
- Changes go through pull requests; CI (`check`, `shellcheck`) must pass. Never merge on the user's behalf.
- `post-daily.yml` and `post-on-deploy.yml` are copies of `nb-app-template`'s, verbatim (the apps/ rule), even though this repository is not deployed.
